# 導讀：自己寫一個作業系統核心（給沒學過作業系統的人）

這份導讀假設你從來沒修過「作業系統」。讀完之後，你應該能用自己的話向面試官說明：
這個專案做了什麼、電腦從開機到出現命令列中間發生了什麼、為什麼要這樣設計、
以及怎麼證明它是對的。

## 1. 這個專案在解決什麼問題

平常我們寫程式（例如 Python 的 `print("hi")`），從來不用管：

* 這個程式放在記憶體的哪裡？會不會被別的程式蓋掉？
* 電腦有 4 顆 CPU，同時有 10 個程式要跑，誰先跑？
* 寫進檔案的資料，突然停電會不會壞掉？

替所有程式處理這些事的軟體，就叫**作業系統核心（kernel）**。Windows、macOS、Linux 都有一個。
這個專案 **wren-os** 就是從零寫的一個小核心：

* 用 C 語言和組合語言寫成，跑在 64 位元 ARM 處理器（AArch64，和 Apple M 系列晶片、手機同一家族）。
* 可以同時用 4 顆（最多 8 顆）CPU。
* 有自己的檔案系統，斷電也不會壞。
* 有一個 shell（命令列），可以打 `ls`、`cat`、`grep`、用 `|` 把程式接起來。
* **同一個核心檔案**可以在兩台不同的虛擬機上開機：QEMU（業界常用的模擬器）和
  **LeapVM**（你自己寫的 Mac 虛擬機）。

這是模仿 MIT 6.1810（xv6）、哈佛 CS 161（Chickadee）、耶魯 CPSC 422（mCertiKOS）
這些課程期末專題的**學習用重做**，不是新發明。程式碼是自己寫的，想法來自這些課程，
README 的 Related work 都有列出來。

## 2. 八個關鍵觀念（每個附一個生活比喻）

### 觀念一：核心是「大樓管理員」

一台電腦上跑著很多程式，就像一棟大樓住了很多住戶。管理員（核心）掌管所有共用的東西：
電梯（CPU）、信箱（檔案）、水電（記憶體）。住戶不能自己去拆電梯，要請管理員處理。

在硬體上，這個「權限差別」是真的：ARM 處理器有不同的**特權等級**。一般程式跑在 **EL0**
（住戶，權限最低），核心跑在 **EL1**（管理員）。EL0 的程式碰不到硬體、也看不到別人的記憶體。
（再上面還有 EL2，是虛擬機用的；QEMU 有時會從 EL2 開始，`boot.S` 會先把自己降到 EL1。）

### 觀念二：從按下電源到出現 `$`

1. **虛擬機把核心檔案載入記憶體**：QEMU 放在位址 `0x40200000`，LeapVM 放在 `0x40000000`
   （兩邊不一樣！），再交給核心一份「硬體清單」（device tree，DTB）。
2. **`boot.S`（組合語言）**：先確認自己在 EL1，蓋一張臨時的「位址對照表」，打開 MMU
   （觀念三會解釋），跳到核心真正的位址。
3. **`kmain()`（C 語言）**：讀硬體清單，找到序列埠（印字用）、記憶體有多大、
   中斷控制器（GIC）在哪裡、硬碟在哪裡；把空的記憶體交給「記憶體分配器」；
   叫醒其他 CPU；建立第一個程式。
4. **第一個程式** 掛載硬碟上的檔案系統，然後執行 `/bin/init`。
5. **`init`** 打開螢幕（`/dev/console`），再啟動 **`sh`**，`sh` 印出 `$ `，等你打字。

整個過程在 QEMU 約 69 毫秒，在 LeapVM 約 41 毫秒。

**比喻**：像開店。店長（`boot.S`）先開燈開門，再看「店內配置圖」（硬體清單）知道收銀機、
倉庫在哪，叫其他店員（其他 CPU）上班，最後讓櫃台人員（shell）開始接客。

**為什麼要讀硬體清單**：QEMU 的序列埠在 `0x09000000`，LeapVM 的在 `0x0C000000`。
如果把位址寫死在程式裡，換一台機器就壞了。所以核心自己寫了一個 device tree 解析器
（`kernel/fdt.c`），所有位址都是「查出來的」，不是「寫死的」。

### 觀念三：虛擬記憶體 = 每個程式都拿到一本「假的通訊錄」

每個程式都以為自己獨佔整個記憶體，程式碼從位址 `0x10000` 開始。但兩個程式不可能真的
都放在同一個地方。秘密是：每個程式手上都有一本**自己的通訊錄（頁表，page table）**，
上面寫「我的 `0x10000` 號房間，實際上在實體記憶體的第幾號」。CPU 裡的 **MMU** 每次存取記憶體
都會自動查這本通訊錄。

* 程式 A 和程式 B 都寫 `0x10000`，但查到的是不同的實體記憶體，所以互不干擾。
* 通訊錄裡沒有的地址（例如 `0`，也就是空指標），一碰就會被 MMU 擋下來，
  核心收到通知，把這個程式結束掉（`segmentation fault`），不會影響其他程式。
* 每一頁還標了「能不能寫、能不能執行」，程式碼不能被改、資料不能被當程式執行（W^X）。

這個專案還做了兩個省記憶體的技巧：

* **延遲配置（lazy allocation）**：程式說「我要 256 MB」，核心先只在通訊錄上記一筆
  「這段可以用」，真的去碰某一頁時才給實體記憶體。像餐廳訂位只先記名字，客人到了才擺餐具。
* **寫入時複製（copy-on-write，COW）**：`fork` 會複製出一個一模一樣的子程式。
  不真的複製所有記憶體，而是讓兩本通訊錄指向同一批頁面，並標成「唯讀」。
  誰先要寫，才幫誰複製那一頁。像兩個人共用一份講義，有人要在上面畫重點才影印一份給他。

### 觀念四：系統呼叫 = 按櫃台的服務鈴

程式想讀檔案、開新程式、印字，都要請核心幫忙，這叫**系統呼叫（system call）**。
在 ARM 上，程式把「我要什麼服務」的編號放在暫存器 `x8`，參數放在 `x0`~`x5`，
然後執行一條特殊指令 `svc #0`，就像按下櫃台的服務鈴：

1. CPU 自動切到 EL1，跳到核心事先登記好的「例外處理表」（`kernel/entry.S`）。
2. 核心把程式所有暫存器存起來（就像先記下客人原本在做什麼）。
3. 依照 `x8` 的編號去查表，執行對應的函式（例如 `sys_read`）。
4. 把結果放回 `x0`，恢復暫存器，用 `eret` 指令回到程式。

一次 `getpid` 系統呼叫，在 Mac 的虛擬化環境下大約 **66 奈秒**。

**一個安全細節**：程式傳來的指標（「把資料放到我的 `0x5000`」）不能相信。核心不會直接去碰那個
位址，而是先查這個程式的通訊錄，確認那一頁真的屬於它、而且可以寫（`kernel/vm.c` 的 `copyout`）。
傳錯指標只會得到錯誤碼 `EFAULT`，核心不會當機。測試裡就有故意傳核心位址的案例。

### 觀念五：排程 = 很多人輪流用幾台電腦

假設有 4 台電腦（4 顆 CPU）、12 個人（程式）要用。規則：

* 想用的人排成一排（**run queue**）。
* 每台電腦有一個管理員（每顆 CPU 的**排程器**），從隊伍最前面叫一個人來用。
* 每個人最多用 10 毫秒，鬧鐘（**計時器中斷**，每秒 100 次）一響就要讓位，排到隊伍最後面
  （這叫**搶占式排程**）。
* 在等東西的人（例如等你打字、等硬碟）不排隊，去旁邊「睡覺」，東西到了再被叫醒
  （**sleep / wakeup**）。

**換人時要記下進度**：換程式的時候，核心要把舊程式的所有暫存器（包含浮點運算用的
32 個 128 位元暫存器）存起來，再載入新程式的。這叫**context switch**，約 350 奈秒。

**多顆 CPU 的難題：鎖**。兩顆 CPU 同時改同一個資料（例如兩個人同時從隊伍拿人）就會出錯。
所以共用資料要上**鎖（spinlock）**：拿到鎖的人才能改，其他人在門口等。這個專案用的是
「抽號碼牌」的 ticket lock，先來先服務。如果有人等了 20 秒還拿不到鎖，核心會直接報錯
「可能死結了，鎖被某顆 CPU 拿著」，而不是默默卡住，方便除錯。

### 觀念六：檔案系統為什麼需要「日誌」（停電比喻）

存一個新檔案，硬碟上其實要改好幾個地方：「哪些格子被用掉了」的表、檔案的資料、
目錄裡的名字。如果改到一半**停電**，就會出現「格子標成用掉了，但沒有任何檔案在用」
或「目錄裡有名字，但檔案內容是垃圾」這種壞掉的狀態。

**比喻**：會計要把錢從 A 帳戶轉到 B 帳戶，要改兩本帳。如果只改了一本就停電，錢就憑空消失。
聰明的做法是：先在**流水帳（日誌，log）**上寫「我要做這兩件事」，最後寫一行「**確認**」，
然後才去改兩本帳。重新開機時看流水帳：

* 有「確認」那一行 → 照著流水帳重做一次（重做一次也不會錯）。
* 沒有「確認」 → 當作從來沒發生，什麼都不改。

所以任何時候停電，結果只會是「全部做完」或「完全沒做」，不會停在一半。
這個專案的流水帳（`kernel/log.c`）還多做了一件事：「確認」那一行附了一個 **CRC 檢查碼**，
是根據要改的所有資料算出來的。如果硬碟出狀況，確認行寫進去了但資料沒有，檢查碼對不起來，
就知道這筆不能信。另外，每個改硬碟的系統呼叫**都要等確認寫進硬碟才回傳**，
所以「程式說存好了」就代表真的存好了。

### 觀念七：同一個核心，兩台虛擬機

QEMU 和 LeapVM 雖然都是「虛擬的 ARM 電腦」，但很多地方不一樣：

| | QEMU virt | LeapVM |
|---|---|---|
| 核心被放在 | `0x40200000` | `0x40000000` |
| 序列埠 | `0x09000000` | `0x0C000000` |
| 硬碟介面（virtio） | 預設舊版（legacy, version 1） | 只有新版（modern, version 2） |

核心的對策：

* **位置不同**：核心不假設自己在哪裡，開機時用相對位址算出來，再把自己對應到固定的高位址。
* **裝置位址不同**：全部從硬體清單查。
* **硬碟介面不同**：virtio 驅動程式（`kernel/virtio_blk.c`）兩種版本都會講，開機時讀版本號決定。

這是整個專案最能證明「沒有寫死任何東西」的地方：同一個 `build/Image` 檔案，兩邊都能開機、
跑完測試。

### 觀念八：怎麼證明它是對的

只說「我試過可以用」是不夠的。這個專案用了五層證據：

1. **單元測試**（在 Mac 上直接跑）：硬體清單解析器、記憶體分配器、ELF 執行檔檢查。
   還會故意餵 20,000 個被亂改過的硬體清單、50,000 個亂改的 ELF 檔頭，確認不會當機。
2. **usertests**（在 wren-os 裡面跑的 40 項測試）：fork、pipe、記憶體不足、
   故意碰空指標會不會被抓到、浮點暫存器在切換程式後有沒有被弄亂……，1 顆和 4 顆 CPU 都跑。
3. **壓力測試**：12 個程式在 4 顆 CPU 上同時 fork、開 pipe、寫檔案 60 秒，每個位元組都檢查，
   最後還要沒有記憶體外洩、檔案系統檢查（fsck）通過。
4. **斷電測試**：600 次，在隨機時間點「拔插頭」（三種方式：在第 N 次寫硬碟前關機、
   第 N 次寫硬碟只寫一半、直接把虛擬機程序砍掉）。每次都重開機、用 fsck 檢查，
   並確認「程式已經說存好的東西」一個都沒少、「做到一半的動作」不會半套出現。600/600 通過。
5. **突變測試（mutation testing）**：故意把核心改壞 8 個地方（例如拿掉一個鎖、拿掉一次 TLB 清除、
   拿掉日誌的「確認」那一行），每一個都必須讓某個測試失敗。8/8 都抓到了。
   這證明測試「有牙齒」，不是怎樣都會過。

**比喻**：考試不只看你答對，還要換題目、在你緊張時考、最後故意把答案改錯看老師改不改得出來。

## 4. 怎麼自己跑

* **最簡單**：在 Finder 雙擊 `開機看看.command`。它會檢查工具、編譯、開機到 `$`。
  有 LeapVM 就用 LeapVM，沒有就用 QEMU。離開：打 `poweroff`，或按 Ctrl-A 再按 x。
* 開機後試試：`ls /bin`、`cat /motd.txt | wc`、`ps`、`sleep 3000 &` 然後 `ps`、`usertests`、`stress 10`。
* 在終端機：`make test` 跑全部測試（約 1 分鐘），`make crash` 跑 300 次斷電測試，
  `make mutants` 跑突變測試，`make bench` 量效能。

## 5. 面試可能會問的 10 個問題

**Q1：作業系統核心到底在做什麼？**
A：替所有程式管理共用資源：CPU 時間（排程）、記憶體（每個程式自己的位址空間）、
硬碟上的檔案，並且隔離程式，讓一個程式出錯不會拖垮別人。程式要用這些資源時，
透過系統呼叫請核心幫忙。

**Q2：為什麼每個程式都可以用同一個位址 `0x10000`？**
A：因為那是虛擬位址。每個程式有自己的頁表，MMU 每次存取都把虛擬位址翻成實體位址，
兩個程式的 `0x10000` 會被翻到不同的實體記憶體。切換程式時只要換頁表的根（`TTBR0`）；
我還給每個位址空間一個 ASID 標籤，所以切換時不用清空 TLB（翻譯快取）。

**Q3：fork 很貴嗎？你怎麼讓它變便宜？**
A：用 copy-on-write。fork 時只複製頁表、把共用的頁面標成唯讀並增加參考計數；
誰先寫才複製那一頁。量測：一個有 4 MB 資料的程式 fork 只要 17.6 微秒，
大約是空程式 fork 的 3 倍，而不是複製 1,024 頁的成本。
陷阱：把父程式的頁面改成唯讀後要清掉父程式的 TLB，不然它會繼續透過舊的「可寫」快取寫進共用頁面。
我的突變測試證明，拿掉這行清除，COW 測試就會失敗。

**Q4：系統呼叫的流程是什麼？**
A：程式把編號放 `x8`、參數放 `x0`~`x5`，執行 `svc`。CPU 切到 EL1、跳到例外向量表，
核心把 34 個暫存器存到這個程式的核心堆疊上，查表執行，把結果放回 `x0`，`eret` 回去。
在 Mac 虛擬化下一次約 66 奈秒。

**Q5：多顆 CPU 時，sleep/wakeup 會有什麼問題？**
A：「遺失喚醒」：程式檢查完條件、還沒睡著之前，另一顆 CPU 剛好發出喚醒，這個喚醒就沒人收到，
程式會永遠睡下去。解法是睡覺前先拿排程鎖 `proc_lock` 再放開條件的鎖，而喚醒也必須拿 `proc_lock`，
所以兩件事不可能交錯。

**Q6：檔案系統怎麼做到斷電不壞？**
A：寫入先寫日誌（write-ahead log）：資料先寫到日誌區，再寫一個附 CRC 檢查碼的「確認」區塊，
最後才寫回原位。重開機時，確認區塊的檢查碼對得上就重做，對不上就丟掉。
而且每個系統呼叫等確認寫進硬碟才回傳。

**Q7：你怎麼證明斷電真的不會壞？**
A：自動化斷電測試 600 次：用固定的亂數種子決定在哪裡斷電（在第 N 次寫硬碟前關機、
寫一半、直接砍掉虛擬機）。程式每個動作前後都印 `OP`/`OK`，測試程式依此建立
「應該存在的狀態」模型；重開機後用我寫的 fsck 檢查一致性，並比對內容必須是
「所有 OK 的動作，加上進行中那個動作的某個前段」。600 次全部通過。

**Q8：為什麼同一個核心可以在 QEMU 和 LeapVM 上跑？**
A：核心不寫死任何硬體位址：載入位址用 PC 相對定址算，裝置位址從 device tree 讀，
virtio 硬碟兩種版本都支援。兩台虛擬機的載入位址、序列埠位址、virtio 版本都不同，
同一個 `Image` 兩邊都通過測試。

**Q9：你怎麼知道你的測試是有效的，不是怎樣都會過？**
A：突變測試。我故意做了 8 個一行的破壞（拿掉 TLB 清除、拿掉記憶體分配器的鎖、
拿掉日誌確認、拿掉日誌重做、拿掉 COW 參考計數、拿掉浮點暫存器保存、漏掉釋放間接區塊、
拿掉 pipe 的喚醒），每個都讓對應的測試失敗。後來又加了 3 個給垃圾回收器和外洩偵測器的，
現在是 11/11 都抓到。

**Q10：這個專案最大的限制是什麼？如果再做下去會改什麼？**
A：排程用一把大鎖和一條共用隊伍，4 到 8 顆 CPU 夠用，再多就會互搶；沒有 signal、thread、mmap；
所有寫檔都要等硬碟確認，所以寫入速度受限（每秒約 10 到 24 MB）。下一步會做每顆 CPU 自己的隊伍、
`fsync` 讓多次寫入合併成一次確認，以及會「打亂寫入順序」的斷電測試。
另外要誠實說：這是學習用的重做，想法來自 xv6 等課程，但程式碼是自己寫的。

## 6. 加碼：垃圾回收器和記憶體外洩偵測器

C 語言要自己 `free`。忘了 `free` 叫「外洩」（leak），`free` 了還繼續用會出大事。
這一節加了兩個工具，都在使用者的函式庫裡（`user/lib/`），核心幾乎沒改：

* **垃圾回收器**（`gc_malloc`）：拿了記憶體就用，永遠不用 `free`，沒人用的東西它會自己收回。
* **外洩偵測器**（`leakcheck 程式`）：程式結束時，找出「用 `malloc` 拿了、沒 `free`、而且已經沒有
  任何指標指到」的區塊，印出大小和是哪一行程式拿的。

模仿的是史丹佛 CS140E/CS240LX 的期末專題，和業界的 Boehm 回收器、Valgrind、LeakSanitizer。
這是學習用的重做，不是新發明。

### 觀念一：「還有沒有人在用」= 從門口能不能走到

回收器不知道程式「以後」會不會用某塊記憶體，它只問：「現在從程式手上拿得到的東西出發，
順著指標一路走，走不走得到這塊？」走不到的，程式就算想用也找不到它，可以收。

比喻：**大賣場關門前清場**。店員從入口（程式手上的變數）出發，沿著走道（指標）把每一區走一遍，
走過的地方貼上「有人」的貼紙（標記，mark）；最後沒貼紙的區域全部清掉（清除，sweep）。
這就是 mark-sweep。兩個東西互相指著對方、但從入口走不到（循環），一樣會被清掉，
這是「參考計數」做不到的。

### 觀念二：入口在哪裡（根，roots）

程式手上的東西只可能在三個地方：

1. **CPU 暫存器**：`user/lib/regs.S` 用幾行組合語言把 x19-x28 等暫存器先存到堆疊上，讓掃描看得到。
2. **堆疊**：從現在的 `sp` 一路到堆疊頂端。頂端在程式一開始（`crt0.S`）就記下來了。
3. **全域變數**：連結器（`user/user.ld`）幫忙標出 `.data` 和 `.bss` 的開頭和結尾。

比喻：**找遺失的鑰匙**，只要翻口袋（暫存器）、包包（堆疊）、家裡的抽屜（全域變數），
其他地方的東西你自己也拿不到。

### 觀念三：「保守式」= 寧可錯留，不可錯殺

C 語言裡一個 64 位元的數字，回收器分不出它是指標還是普通整數。所以它很「保守」：
**只要長得像指到某個物件，就當它是指標**，那個物件就留下來。

比喻：**大掃除時看到一張寫了地址的紙條**，不確定是不是重要的，就先不丟那個地址的箱子。
代價是偶爾留下真正的垃圾（false retention），但絕對不會把還在用的東西丟掉。
為了少誤留，回收區放在 4 GiB 以上的位址，所以一般的小整數（計數器、長度）永遠不會像指標。

### 觀念四：外洩偵測器是同一套方法換個用法

外洩偵測器也是從同樣的入口出發標記，只是不收回，而是把「沒被走到、也沒被 `free`」的區塊**列出來**。
每個 `malloc` 區塊的標頭記下「是誰拿的」（呼叫 `malloc` 那一行的返回位址），所以報告能說出是哪個函式漏的。

比喻：**圖書館盤點**：從借閱紀錄找得到借書人的書都沒事；書不在架上、也查不到是誰借的，就是「遺失」，
清單上還寫著當初是哪個櫃台借出去的。

`leakcheck` 怎麼讓任何程式都開著偵測？它在自己身上設一個旗標（`personality()`，抄 Linux 的做法），
這個旗標 `exec` 換程式之後還在，函式庫的 `exit()` 看到旗標就先印報告。這是唯一的核心修改，27 行。

### 自己跑跑看

```
$ gcdemo          # 一直做清單、樹、環然後丟掉，看 heap 會不會一直長大（不會）
$ leakcheck leakdemo        # 正好報出故意漏的 7 塊，共 352 bytes
$ leakcheck leakdemo clean  # 修好的版本：no leaks
$ gctest          # 13 項回收器測試
```

### 面試可能會問的 4 個問題

**Q1：保守式回收器會不會把還在用的記憶體收掉？**
A：只要指標用正常的方式存在暫存器、堆疊、全域變數或其他活物件裡，就不會：任何看起來像指標的字都會讓物件留下。
會出事的是「把指標藏起來」的程式，例如只存 `p ^ key`、存在沒對齊的位址、或只存在 `malloc` 的記憶體裡
（那一區不掃）。測試裡我故意把指標只放在 x19-x28 和 d8 這 11 個暫存器，確認它們都被留下；
也做了突變測試：讓 x27、x28 不被存下來，測試就會失敗。

**Q2：為什麼只要存 callee-saved 暫存器？x0-x18 呢？**
A：照 ARM 的呼叫慣例，呼叫函式時 x0-x18 本來就可能被蓋掉，所以編譯器在呼叫 `gc_collect` 之前，
已經把還要用的值存到堆疊上了；只有 callee-saved 的 x19-x28、d8-d15 可能還「只」在暫存器裡。

**Q3：mark 的時候用遞迴會怎樣？你怎麼處理？**
A：一條很長的串列遞迴下去會把堆疊用光。我用一個固定大小的「標記堆疊」（8,192 格）。
滿了也不丟：物件已經標記，只是孩子還沒掃，所以設一個旗標，掃完後把所有已標記的物件再掃一遍，
直到沒有溢位為止。主機測試故意用只有 4 格的標記堆疊跑模型檢查，確認結果完全一樣。

**Q4：跟 malloc/free 比，回收器比較快還是比較慢？缺點是什麼？**
A：在建樹的測試裡，`gc_malloc` 每個節點約 12-14 ns，`malloc` + `free` 約 9 ns，慢 1.3 到 1.6 倍；
多出來的幾乎都是回收的時間，主要花在每次都重新標記那棵一直活著的大樹。暫停時間大約每 MiB 活資料 140 微秒。
缺點：不會壓縮（碎片留著）、每次都停下整個程式、可能誤留垃圾。分代回收可以解決「一直重標老物件」，
但這個版本刻意沒做。
